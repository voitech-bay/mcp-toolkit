Where it lands

Six stages each POST to one endpoint, voitech.up.railway.app/api/n8n/workflow-results, not to Supabase directly. Each row is the whole stage item plus workflow_name, entity_key, run_id, persisted_at. Writes are plain inserts per run; reads go through a view that keeps the newest row per (entity_key, workflow_name).

06 Known gaps

Found while tracing. All verified in code. None are fixed here except the first, which was fixed on discovery.

Fixed during this trace

The allow list was deleting exactly the systems we went to get. Synthesis filtered tech_stack through a whitelist of ~90 known enterprise products. Turvo, Orderful, DispatchTrack, Onward and Excede all fail it; only generic names like Snowflake and Salesforce pass. That silently defeated the whole profile extraction path.

Profile sourced systems now skip the whitelist, since it is a list of what we already know and the point of reading an engineer's role text is to catch what it does not contain. The deny list still applies, so Office, Excel and operating systems are still stripped. Verified: Turvo, Orderful and DispatchTrack now reach the brief; Windows and Office still do not.

GapDetail
Discovered contacts carry no emailThe CSV shape has email; the discovered shape does not. Prospeo returns a verified but masked address, {status:"VERIFIED", revealed:false, email:"j******@rlx.us"}, and we discard it. Email is the Smartlead channel, so discovery currently cannot feed it.
it_headcount_sampled counts every contactNot just IT, despite the name. It feeds the org maturity judgement. The intel tier change adds up to 8 IT individual contributors per company, so this number now runs higher than it used to and may skew that read. This one is a consequence of the recent change.
Dead fallback in Build companiesIt reads enr.summary || enr.current_role_description, but current_role_description is never a key on enrichment — it only exists on per_contact_summaries[].
The POV validator checks data the agent never sawThe agent is not given research_source_urls, yet the validator rejects any evidence_sources or headline_facts[].source not traceable to that list.
Two drifted department classifiersfuncClass() in the intel lane and jobDept() in the jobs lane classify the same concept with different regexes and different output sets.
_vv_rollups_* is never prunedThe other two side channels delete sibling execution keys; this one does not. Build companies re-keys defensively, which is why it has not bitten yet.
Unused Prospeo signalEvery record carries job_history[] with vendor classified seniority, departments and duration_in_months. The title classifier re-derives all of it from the title string alone.
